**Result.** Keep the right-hand XWE ciphertext table and compile the entire left-hand key table into one compute-and-compare program. The program recomputes a residual ABE key from its row address and uses it internally. A consistent NAND trace is the certificate for using that row with the indicated column. The encryption bit appears only in the right-hand table. This places the missing cryptographic step at a specific *change of key-issuance algorithm* at one rejecting column. The two algorithms, their randomness, the side information and a fixed decision-LWE challenge embedding are specified below. No indistinguishability result for that change or machine cost certificate is known here.

### Algorithms

Use the public-key, one-bit BGG+ KP-ABE template of the DAG XWE note, with a public matrix setup, short-preimage policy keys and acceptance convention 1. Use the multibit-output compute-and-compare construction of Goyal, Koppula and Waters (GKW) with a one-bit payload. Fix the parameter sets, clocks, tape widths for all samplers, security of the lattice parameters, and common padded program shape before seeing the statement. These numerical choices remain open. Interpret truncated-sampler failure as rejection. All setup is private work by the encryptor. [BGG+ XWE design](pq-we-xwe-from-bgg-abe-design.md) and [GKW, FOCS 2017, pp. 612–613](https://ieee-focs.org/FOCS-2017-Papers/3464a612.pdf).

* Split 128 witness bits into a left bits and b right bits, a+b=128. For each left address x, define the policy f_x(y)=φ(x,y) by fixing those a inputs in the original gate list. Normalize forward references to true as in the registered relation. Sample (pk,T) by ordinary ABE setup, a t-bit lock L (draw uniformly and map zero to a fixed nonzero string), and M,r uniform over binary matrices and vectors of dimensions h-by-a and h. Here h is the fixed number of random bits used by a clocked key-issuance call. Its tape at x is r(x)=Mx+r over GF(2). It is uniform at each fixed x. There is no independence assertion about three or more rows.
* Form a deterministic circuit P. Its input is (x,y,v,D), with v the claimed sequence of all 4,096 gate values and D a vector of t one-bit ABE ciphertexts for the same right address. Check fixed lengths, the address labels, every NAND against the same original input and earlier trace, and the final bit. On failure output the t-bit zero string. Otherwise compute k_x=KeyGen(pk,T,f_x;r(x)), decrypt each component of D using k_x and the indicated attribute y, and concatenate the t resulting bits. Return zero on any decryption or sampling error. Zero never equals L. Mapping the exceptional all-zero draw changes a uniform-lock law in total variation by 2^-t.
* Publish Z=Obf(P, payload=1, lock=L), pk, and the ordered right table. Let e be the public t-bit vector with only bit 1 set. At each right address y encrypt the bits of L if β=1 and L XOR e if β=0, independently randomized at every (y,j). Encode addresses canonically. The key-generation tape seed, master trapdoor and lock stay inside the construction. The tested function P contains no L, β or right table. Only the obfuscation takes L as a separate argument.
* Dec splits its supplied witness, computes the trace once, selects D_y, evaluates Z(x,y,v,D_y), and returns 1 exactly on the payload 1. Reject invalid traces explicitly before calling Z. The program's own check matters since arbitrary callers have its bytes. No left key leaves the evaluator. The trace binds the left address, right address and every repeated wire. Public KP-ABE ciphertexts can be freshly generated or relabelled. This construction needs no origin authentication on arbitrary ciphertexts: false-statement security below gives the attacker the *entire program* to use with any bytes, and honest correctness uses the specified D_y. The trace condition is a functional property of the tested circuit, not an argument for hiding its implementation.

For any fixed valid witness, if the selected key and all t decryptions are correct, the value compared is L for β=1 and L XOR e for β=0. These differ for every lock. A union bound charges key-sampler failure, t times the per-bit decryption error (or a single joint bound), and the selected obfuscator evaluation error. When costing correctness use bounds for the actual fixed-witness marginal including its seeded key. The remapping of the zero lock contributes no honest comparison error. The sum of the implementation error bounds must be at most 2^-128. One program invocation always uses a single x, independently of how many other rows the adversary evaluates.

### The setup switch to prove

Here is a targeted experiment for the concrete BGG+ and GKW algorithms. It permits locally empty columns of otherwise satisfiable circuits. This local version specifies precisely which fact about the circuit is available in the reduction.

1. Fix φ and y* with f_x(y*)=0 for every x. Fix an arbitrary public subset J of right addresses. In both laws sample L,M,r as above. Define Aux_J(pk,L) to be the full ordered table of fresh ordinary encryptions of the string L on columns in J and L XOR e on all other columns. Its inputs exclude any sampler trapdoor. All exposed labels, framing, sizes and evaluator clocks agree.
2. In Real sample ordinary (pk,T). Build P with the ordinary trapdoor preimage sampler. Output (pk,Obf(P,1,L),Aux_J(pk,L)).
3. In Prog draw the *uniform design* A and target column u, independent of the statement, as in the registered decision-LWE matrix challenge. For attribute coordinates (including the constant lane with its specified value), draw the short BGG simulation matrices R_i and set B_i=A R_i+y*_i G, in the orientation of the XWE note. Make the same public pk layout. In the program replace the master trapdoor by these R_i and the fixed y*. On input x propagate the short matrices through the gates of f_x by BGG EvalSim. At the output B_f=A R_f+f_x(y*)G. With acceptance convention 1 the ABE key is a short preimage for [A | B_f-G] at target u. On this column B_f-G=A R_f-G has the invertible gadget tag -1. Use SampleRight with R_f, identical Gaussian target width, and the specified row tape r(x). Return miss on failure, including an invalid tag. Pad both program variants to the same supported shape, then output the tuple of the same format using this program. There is no trapdoor for challenge A. The extra test that φ(x,y)=1 inside either program is at the *supplied* y, not at y*.

**Open leaf.** For J immediately before or after a target column in a fixed public switch order, bound the quantum distinguishing gap between Real and Prog by ε_I at a stated cost using only registry premises (or statistical steps). For fixed instantiations and clocks, the experiments specify the full distributions, including compiler coins and the correlated right table. A useful stronger subgoal is the same switch with an arbitrary fixed J. The statement does not ask for a compiler hiding arbitrary equivalent functions. It names one pair of preimage algorithms, one programmed matrix design and one locked test with fixed payload. It is a proof obligation, not a proposed assumption. A proof that changes individual address tapes must account for the actual joint law of M,r. The proof may enumerate addresses, but must charge its time and advantage loss.

The usual BGG argument compares short-preimage *outputs* for a queried rejecting policy. Here the adversary sees bytes produced from a circuit containing the sampling algorithm and its seed. Even agreement of all honest tests does not compare those bytes. The GKW random-lock theorem applied to an isolated P omits Aux_J. In particular, given the unobfuscated **real** master trapdoor and the public table, one can issue an always-accept key and decrypt every component. At the all-lock endpoint this returns L from one column. At the flipped endpoint the same reader can undo the public flip. Moreover, raw programmed R_i are unsafe to reveal as an independent-lock justification in a multi-column view: for y′≠y*, an equality policy for y′ rejects y*, so those matrices issue a key that decrypts y′. Knowing which hybrid is under discussion identifies the plaintext there. The public output of the wrapper exposes the programmed issuer only through its compiled bytes; the wrapper also uses R_i privately to synthesize the challenge lanes. This is a direct falsification of a reduction giving the simulator the raw real program and applying an independent-lock argument to that full view. It is not an attack on the published Z. Giving only the selected-row decryption oracle to a distinguisher would discard precisely this unresolved issue.

### Fixed-assumption hybrid after the switch

Hybridize from the empty J to all right addresses. At column y* change the setup to Prog. Only the first bit ciphertext differs between the two table laws; all other bits in that column may be honestly encrypted using the public key. Construct the sealed program from public design and the reduction's known R_i before receiving any LWE response values. All companion encryptions and compiler coins are sampled locally. In the selected BGG encryption embed the response row on [A | u], using the same unknown secret for its two parts. In registry orientation the challenge design has one row per column of A plus one for u, and must use the same secret and non-flooded error laws as this ABE instantiation. Synthesize the attribute lanes by multiplying the A part by R_i and adding fresh flooding noise, and add the indicated message offset to the u part. On real LWE this requires a statistical comparison of shifted noise to the honest Prog ciphertext, jointly with R_i, even if those are leaked in full. On uniform LWE the u response is independently uniform; translating this component by the bit offset has exactly the same law. Run the real comparison in reverse at the other endpoint and switch back to Real. Reuse of the same lock or compiler does not create a fresh-sample claim about two adjacent views. Each reduction samples one complete classical challenge for one invocation of the adversary.

Writing Q=2^b, the acceptance-probability gap is at most Q(2ε_I+2ε_LWE+2δ), where δ bounds a real-side target-sample statistical error, and ε_LWE is evaluated at the whole wrapper cost. Include any losses in the setup switch in ε_I. The argument uses classical sampling, postprocessing and a one-shot quantum test. It uses no rewinding or observation of superposition queries. The same conditional hybrid applies to classical encoded machines. A concrete proof must show that this bound squared times 2^128 is at most each adversary's cost, including statistical slack, simulation time and any nonuniform indices. Using the pair of strings at Hamming distance one reduces the hybrid count from t·2^b to 2^b while preserving a long secret lock. At b=12,t=256 there are 2^12 target positions, hence 24 bits of squared-advantage loss even before the constants and reduction overhead. The registry's decision-LWE strength at the required parameters remains to be certified; its Lean machine security does not certify a quantum hardness level.

### Size and comparison

Let K be the cost of compiling one residual policy-key generator with its bounded sampler and t decryptions *as a Boolean circuit*. It includes condition checks, sampler precision and seeded tape expansion. Let O_E(K), O_D(K) be the concrete costs of producing and evaluating its locked encoding. Honest work includes setup, O_E(K), t·2^b one-bit encryptions and their writes, a table scan for Dec, O_D(K), and both machine description lengths. The compact left representation has size |Z|, independent of the number 2^a of left addresses when the chosen circuit description and sampler use space polynomial in a. GKW's concrete compilation may dominate every other term. Confusing gate-level sampler cost with native keygen runtime would conceal this term. With b=12,t=256, even if all other stages were free the average production cost per one-bit right component must be at most 2^80 tape steps. Positive overhead makes the available budget smaller. No parameter choice here is certified to meet the total 2^100 cap.

* BJKPW Theorem 3.2 enumerates both the left keys and the right ciphertexts. This design retains the public-key single-attribute right table and seals KeyGen itself. The key circuit supports every NAND list in the relation, including labels with large cut width or full evaluation rank. [BJKPW, Theorem 3.2](https://eprint.iacr.org/2017/874.pdf).
* AMR-style tree encodings supply a constrained evaluation and require a compatible master evaluation. The positional GGH15 note already has a path tracker feeding a BGG leaf. We discarded a proposed path-product generator after finding this overlap. The present construction uses no root/path product or generic public master evaluation. The two-input ABE note combines slot-dependent secrets and faces rectangle and trapdoor-simulation issues. Here there is a single attribute per ABE call and the only derived object exposed is a locked test.
* In PR #109 (head 660eea090e8fe8223c22c04a596f4b14a7c92544), symbolic slices publish coefficients for affine residual equations and the explicit-table decision boundary counts materialized path labels. Here ordinary decryption inside the compiled program executes the original circuit policy. The hard leaf concerns two concrete issuance circuits with correlated auxiliary encryptions. Earlier compute-and-compare notes already identify the dependent-lock problem; the new ingredient here is the explicit selectively programmed replacement for the real master and the per-column switch above. [PR #109](https://github.com/MachinaIO/SigabaPark/pull/109).

### Falsification and the linear alternative

For the exact linear alternative, suppose the secret as a function of x lies in a field-linear coefficient space U of functions on the a-cube. Keeping every BGG attribute-offset product x_i·s(x) in that *same* space for all possible s requires closure under each coordinate mask. For a supported address x, start with f in U with f(x) nonzero. At each coordinate retain the matching half, using f minus its positive mask when x_i=0. After all coordinates only f(x) times the indicator of x remains. Normalize. Thus U contains every supported point indicator, and full support forces dimension at least 2^a. The DAG proof formalizes the point-indicator assertion. This excludes an exact, full-support, same-space linear representation; it does not bound nonlinear programs, noisy approximation, or representations using different spaces for different offsets.

A scalar exact control at q=101 recovered a common unrefreshed secret for every nonzero scalar from the two slots sB and s(B-G), by subtracting and dividing by the unit G. A refreshed three-bit path control gave the intended slot offsets in all 800 checked cases; this supplied no evidence of hiding. For the sealed design an ideal-functionality check enumerated all 625 two-NAND gate lists with two witness bits and each pin in 0..4, retaining default-true forward reads. Across 20,000 choices of address, claimed trace and bit it returned the bit on valid accepting traces and zero otherwise for nonzero lock 3. There were 100 false circuits and 170 locally empty columns of satisfiable circuits. These tests check framing and quantifiers. They do not instantiate a cryptographic sampler or obfuscator.
