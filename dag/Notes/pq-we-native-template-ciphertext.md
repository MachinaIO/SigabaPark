## Fixed public templates and an actual string-output primitive

Consider the selective serial MIFE compiler in BKS, Appendix A.2, Figures 5 and 6 (pp. 41–42). At rank r its key issuer D takes a child master, PRF key K and selector w. Under ordinary inputs it issues a child functional key for the merged-input circuit C_f using coins PRF(K,z). With an absent child master it returns the programmed key u. The aggregator AGG receives the other r−1 slots and outputs a serialized tuple of child ciphertexts, one per child coordinate. It has a tag-controlled override that returns the supplied tuple. One recursive decryption computes this tuple, one outer base decryption computes the child key, and a second recursive decryption consumes both. The final output of the full WE is one bit. Every intermediate serialization has its own statically bounded type. [BKS, Appendix A.2](https://eprint.iacr.org/2015/158.pdf)

For one fixed public circuit shape write F(a,m), where a contains the remaining private parameters. Rank, shape and the public statement may be known to everyone in the WE game. If several templates share a master, include their dispatch tag in a and pad to a common input/output shape, with an explicit parse rule. The evaluator, output width and bounds cover *all* functions and plaintexts invoked in the security hybrids, including the override branches. In a proof using fixed nonuniform circuitry for a public statement, the implementation still needs a uniform way of generating that circuitry and must charge its time and description.

A native one-key candidate of the SS10 type for F uses one public-key encryption key pair for each private parameter bit position and each polarity. The functional key selects one secret key per position. For a message m, garble the fixed circuit F(·,m) once and encrypt each input label under its corresponding public key. Evaluation recovers the selected labels and decodes the entire output. With d parameter bits there are 2d public keys, d selected secret keys, 2d ciphertexts for labels and one new garbling per encryption; include selectors or an equivalent decoding convention. Output decoding and the garbled gates cost work and bits. There is no separate secret key per output bit. This replaces a universal circuit by a common family evaluator only when that family includes the hybrid programs. A master with two different functional keys is outside this one-key guarantee. [AMVY, Remark 3.2](https://eprint.iacr.org/2021/848.pdf), [Garg–Goyal–Lu–Waters, discussion of SS10](https://eprint.iacr.org/2021/847.pdf)

Putting SS10 directly into AMVY §4.1 gives a bounded-family instance: their CPFE key takes the complete inner public key as its input and their encryption circuit produces the complete inner encryption and garbling. In addition to the inner function key, the resulting user key carries that CPFE key. The length of the inner public key determines the CPFE input width, and the inner encryption circuit determines its padded circuit-size parameter. Reproducing the paper's general succinctness assertion would require its specific succinct single-key primitive. For fixed bounded templates the following direct transposition saves this extra layer.

## One fixed-bound transposed CPFE plus BS privacy

Instantiate AMVY's bounded **ciphertext-policy** scheme from §§3.2–3.3, with adaptive simulation security for bounded circuits (Theorem 3.6). Encryption takes a circuit, while a key takes a bit string. Choose one known collusion bound Q for each master, including every relevant hybrid query. This uses the bounded scheme directly and omits the lambda-element portfolio of keys introduced in §3.4 to support an initially unknown Q. In the portfolio construction only the bucket selected by Enc is used by Dec, so for fixed Q that bucket has the same marginal transcript once all unused components are projected away. In the redefined scheme use that one bounded game per master throughout.

* Setup the private base with the CPFE master-key pair and two independently sampled symmetric secret keys k0,k1.
* To issue a key for a, compute fixed-width symmetric encryptions c0,c1 of a under k0,k1 with fresh coins. Issue one CPFE key for the string v=c0||c1. Use a public fixed parsing convention.
* To encrypt m, use CPFE encryption for a padded circuit P on v. In the honest branch P returns F(SymDec(k0,c0),m). Its other branch and the symmetric key k1 are used just as in the BS hybrids. Precisely, the conventional message-private base encrypts a data tuple (mL,mR,kL,kR) by encrypting the circuit which uses the left decrypted parameter when kL is present and otherwise the right one. BS encrypts (m,⊥,k0,⊥) in the real scheme. Defining outputs on malformed inputs/padding must be deterministic and common to the games.
* Decrypt with the CPFE ciphertext and v-key. If F is a D template its output type is one serialized child functional key. If F is an AGG template its output type is the framed tuple of ciphertexts. The evaluator performs the child setup expansion, key generation or encryption, PRF evaluation, framing and output writes wherever its active branch requires them. Sharing public code saves the associated key payload only. Gates for reading all secret parameters and generating actual results still count.

This is the BS double-encryption construction specialized to an evaluator for a parameterized family. Its ordinary-function key before the BS step evaluates one fixed P(v) and message privacy follows from CPFE circuit hiding on equal-length circuits agreeing at all queried v. The SKE plaintext can be just a if its public evaluator is identical on both sides. In particular this does not require symmetric encryption of an entire hardwired gate listing for every output bit. [BS, §4, Fig. 1 and Theorem 4.1](https://eprint.iacr.org/2014/550.pdf), [AMVY, §§3.2–4.1](https://eprint.iacr.org/2021/848.pdf)

A private child master can also have a seed representation. Suppose an honest private scheme has a fixed, bounded setup coin tape of L bits and an API exposing only key and encryption oracles. Use a fresh secret seed s, expand it using a secure PRG to L bits, and reconstruct the original master by deterministic setup on those bits inside each oracle algorithm. Use independent ordinary coins for each call where the base scheme does so. Replacing the PRG tape by a uniform tape in a fixed-side oracle experiment needs one PRG challenge: a simulator given the tape can run setup and all calls without knowing s. The two-sided game costs at most two such transitions per independently replaced master. This argument assumes the caller cannot inspect the master representation through the API, and no public setup output inconsistent with the reconstructed tape. It applies at the private child interface, with D and AGG using that new interface and with their proof programs resized. The literal holder of the child seed could generate arbitrary keys: handing it to the public in place of a functional key would change the primitive. Recomputing at nested calls has a real cost. Correctness with setup-dependent failure must be re-established for the seeded distribution, or inherit a quantified error with a PRG loss for an efficient correctness test.

## Ciphertext-side threshold for the strict 32-bit run target

In the bounded scheme AMVY Equation 3.2 has exactly 2 Q N h IBE ciphertext fields, where N is the RDMPC server count and h is the length of the encoded key input. Equation 3.1 contains n h IBE secret-key fields per functional key with n selected servers, plus the group and subset description. The ciphertext also pays for computing Q RDMPC encodings, QN garblings and 2QNh IBE encryptions. These counts survive the transposition. If Q is rounded to a supported dyadic bucket, count the rounded value. N, n, h, the circuit-size bound, IBE key length and IBE ciphertext length may vary by rank. The full RDMPC/IBE/garbling costs are additional to lower bounds based on counting fields.

Let p be the number of prefix bits handled by a table of function keys, and b1,...,br the widths of the encrypted slots. Their sum including p is 128; p=0 permits one top key. Put b0=p. At honest setup level i the key demand is at least 2^b(i−1) and there are 2^bi base encryptions. Hence if every relevant level has N h w ≥ U, with w the minimum width of an explicitly written IBE ciphertext field, the output costs at least 2U times the sum of 2^(b(i−1)+bi) over i=1,...,r. No simultaneous use of all Cartesian assignments was counted. Hybrid capacities can raise Q further.

If r ≥ 32, the literal decoder already makes at least 2^32−1 base calls; any nonempty encryption adds work. Otherwise, for r≥1 partition the list (p,b1,...,br) into consecutive pairs, plus a final singleton if needed. Each pair uses a distinct charged adjacent edge, and a final singleton uses the still-unused edge ending at that singleton, whose other width is nonnegative. Thus the sum of 2^e over those at most sixteen groups lower bounds the required row count. In the zero-suffix case the prefix table by itself already has 2^128 rows. For grouped exponents totaling 128 the sum is at least 4096. The theorem native_ciphertext_rows proves the grouped inequality and the final multiplication. Its tangent bound is 2^e ≥ 256e − 1792, with equality at e=8 and e=9. Falsification checked all e=0,...,255 and the balanced fits for each possible group count before proof.

Consequently U ≥ 524288 already exhausts the 2^32 target for the explicit native ciphertext layout, across every choice of p and suffix widths. For example, N ≥ 16, h ≥ 256 and w ≥ 128 at every charged level suffice. These are transparent parameter conditions, **not** a concrete security estimate from asymptotic constants. At r=8, p=0 and all b_i=16, a single interior level with N=h=w=1 already needs at least 2·2^32 bits from its adjacent 65536-by-65536 demand. The definition WE_CircuitSAT_Capped itself has cap 2^100; the 32-bit threshold is the stronger research target. Schemes batching IBE fields, altered dispatch or nonliteral decryption need their own accounting.

## The programmed output reappears as an input

In the literal BKS D template, the override u is an input constant. In the switched hybrid the reduction receives a child key from the challenge and installs it in this slot. Even if the honest override is ⊥, a fixed-width direct encoding that can carry an arbitrary K-bit child key allocates at least K private parameter bits. If a deterministic evaluator must return every possible K-bit override exactly from its private representation, even an arbitrary redesigned fixed decoder needs that many bits by the theorem override_width. This formalizes the full-domain condition; valid child keys could form a smaller set.

For the direct CPFE/BS implementation, suppose parameter ciphertexts are fixed-width perfectly decryptable encodings of all parameter strings and that the generic encoded CPFE key input supports exact projections of all its bits. Then each symmetric ciphertext has width at least that of the plaintext, and h is at least the raw width of the pair by the same injectivity argument. For randomized RDMPC input encodings with perfect correctness, fix one supported encoding per input; different inputs have disjoint supports because a projection circuit separates them and its offline randomness is independent. If the needed correctness is merely approximate, this counting argument needs a quantitative replacement; it is not obtained by fixing coins in a high-error union over exponentially many inputs. The explicit uncompressed field layout can alternatively be checked directly on concrete algorithms. Under these conditions h ≥ 2K, and writing n h fixed secret-key fields of at least s bits makes the enclosing key at least 2 n s K bits. This is feedback from the *hardwired override*, not an output-wire lower bound. The AGG bypass tuple analogously occupies input fields v_i of the lower-coordinate encrypted messages, so their lengths affect the size and time of the corresponding circuits as well. A real fresh child setup seed cannot stand for an independently supplied opaque challenge key or ciphertext when its issuance coins and master are unavailable.

## Eager child keys for the known top query table

There is a way to eliminate one entire D layer in the *published WE package* for a known query table. From the original public package retain every inner AGG key and all the shared later-coordinate ciphertexts. For each of the t outer function keys and each of the n1 first-coordinate ciphertexts compute the raw base decryption used by BKS and put its result in a public indexed header; omit those t outer keys and the outer portion of those n1 ciphertexts from the transformed package. An honest sender can produce the header directly: choose the same independent z_f tags, the same independent per-row child masters m_j and PRF keys K_j, and issue

    header[f,j] = Child.KG(m_j, C_f; PRF(K_j,z_f)).

Use those *same* row masters and PRF keys in the row aggregator keys and keep the original common inner master for later-coordinate encryptions. This direct sender skips outer base setup, key issuance and encryption. Dec fetches its header entry, uses the selected AGG key on the shared encrypted suffix to derive the child ciphertext tuple, then decrypts that tuple with the fetched child key. The correctness argument uses the genuine compiled child algorithms at their respective ranks.

On a fixed challenge side the direct package and public transformation couple whenever all t n1 original outer decryptions return their specified child keys. With a uniform per-pair bound ε for this honest correlated query distribution, the union bound gives statistical distance at most t n1 ε. The transformation from the original hiding experiment uses only its public transcript, including when its observer is quantum and receives classical data. The direct sender's ordinary gap is bounded by the original gap plus 2 t n1 ε, charging the t n1 outer decryptions to the reduction. No BKS hop was justified by equality merely after postprocessing. This is a proof by postprocessing of the completed original package. It assumes security of that original ideal construction at its actual reduction cost; it does not require the honest original implementation to meet the WE cost target.

The header costs the *sum* of t n1 child-key widths, with t=2^p for a prefix of p bits. It removes the rank-r functional key carrying the padded override altogether. It keeps n1 aggregate keys under one inner master and independent starred masters per row. Ordinary prefix peeling issues prefix-specialized function keys under one suffix master; its keys and tables have a different joint distribution. Adding a mask and publishing an opening recoverable for every (f,j) supplies no further secrecy in this full public view. For a single rank this defers the longer key width one step: the lower-rank issuers and bypass tuples still have to support BKS, and recursively disclosing *all* results may multiply further row counts. One must reprice the transformed package rather than apply the preceding literal-layout floor to it. A concrete trade is the removed outer costs (t outer keys, n1 outer ciphertexts and their generation) against t n1 child keys, their generation and table access. This is an intermediate construction, with no under-cap parameter row certified.

## Security accounting and remaining construction choice

For each master let q bound all requested keys and M bound all challenge messages in the relevant hybrid. Simulate all but one of the M ciphertexts by public CPFE encryption with fresh coins and retain at most q key queries, including adaptive queries permitted by the game. Interpolate the M left/right pairs in order. For each pair the two challenge circuits have equal shape, and they agree at every queried v by the BS validity condition. Moving from real-left to simulation to real-right thus costs at most 2M times the one-challenge adaptive simulation gap in ordinary output-probability normalization, assuming a common ideal interface, admissible auxiliary input and quantum reductions. Using only nonadaptive single-challenge simulation would miss post-ciphertext key queries. In BS's four changes, two switch FE messages and two switch the SKE encryption of each key's parameter. Under single-challenge CPA bounds this yields at most 4M times the CPFE simulation gap plus 2q times the SKE gap for this base comparison. These are upper loss counts, not honest algorithm costs. Charge other encryptions and oracle emulation to each reduction's clock.

At each rank r>1 budget the real outer master for the prefix keys or inherited aggregator keys and the first-slot ciphertext list; budget the inner master recursively for the remaining table plus the first-slot aggregator queries. In A.11 the starred child must answer all relevant child key and coordinate-ciphertext challenges: it can see up to T of each query type after BKS's uniform equalization with T bounding all original lists. Finiteness at fixed ranks alone gives no numeric reduction clock. With the comparison schedule from A.6–A.16, budget 3T+2 recursive child terms (including the typed starred child at A.11), 2T+2 native base terms, and 2T PRF terms per level. Use the base factor above, PRG setup switches where used, and an extra normalization factor of two if bounding ordinary gaps by converting fair-bit biases conservatively. For a flattened schedule of total weight W and single common bound δ² ≤ ρ cost(A)/2^P, a sufficient strength in the absence of additive errors is P ≥ 128 + ceil(2 log2 W) + ceil(log2 ρ). Include correctness losses, tag collisions and simulation errors separately. Full-view quantum security needs concrete quantum-secure IBE (with the requisite receiver-selective opening transformation), RDMPC, SKE, PRF, garbling, PRG when used, composition with quantum auxiliary state, and explicit reductions to the allowed registry. The cited theorems provide no certified parameters or canonical clocks for the present instance.

A remaining design choice is an FE proof/program supporting a compact *challenge-compatible* reference to a child key or tuple instead of a literal override. To pass this test, specify who creates the reference from the challenge response, what correlated public data are charged, and how D's absent-master branch returns the identical distribution. Alternatively a non-RDMPC bounded primitive with a smaller joint ciphertext layout would avoid the field-count test. Neither replacement is established here.
