The [two-join router in PR 169](https://github.com/MachinaIO/SigabaPark/pull/169) admits a message-only implementation using one fixed expansion per nonterminal. It accepts independent uniform source labels with a static authorized subset. The accompanying finite-control definition is a concrete SigabaNeo.Machine for its generator. The full packet assembly and route wrapper below have explicit clock and state bounds by construction; they have not been submitted as registered WE machines.

### Full local experiment

Independently choose a uniform 256-bit seed at each vertex. Public row bodies are one destination seed xor the unique parent-incidence pads, one or two per row. Give the first and second halves of a single fixed 512-bit ChaCha20 block to the first and second outgoing incidence of a vertex. For degree one use its first half. Use RFC 8439's 20-round IETF block including feedforward, a zero 32-bit counter and a zero 96-bit nonce, little-endian words and little-endian bits within each byte. The terminal emits only β xor bit zero of its unexpanded seed. An honest decoder receives actual opening strings for its compatible source triple (A_i,J_j,C_k), i≠j and k≠j. For each range it follows the public unary chain from the selected i or k toward j, then opens the corresponding two-parent join. It obtains the real terminal seed and the correct bit. Arbitrarily proposed intermediate labels have no public checker.

Fix any static set of source openings independently of all keys. A local supplier accepts this exact authorization mask on its input and outputs flags plus actual source keys for authorized entries, zeros otherwise. The adversary can pool the union. A source is live iff opened; a derived vertex is live iff some incoming row has all parents live. In the dead-terminal case switch each dead nonterminal from the real doubling output to a fresh independent 512-bit word in topological order. Every row into a currently challenged dead nonsource has a dead parent switched earlier. Integrate out one independent incidence pad for each such row, giving uniform incoming bodies instead of using the unknown challenge seed. Source opening data never contains a dead seed. The challenge output itself gives all outgoing halves even when it has two different destinations. Sample all other seeds and rows and keep every body into a live child. This is one complete postprocessing reduction per switched vertex. Distinct seeds are sampled independently with replacement, and the real deterministic function agrees automatically on any accidental equality; an independent ideal word at a hybrid occurrence is the very change being bounded. In the final hybrid flip bit zero of the dead terminal key together with bit zero of one unused-elsewhere switched parent pad on each terminal row and flip β. This measure-preserving bijection keeps every body, opening, and the masked bit. The companion Boolean lemma checks one row. With D dead nonterminals the difference of real acceptance probabilities across the two β values is at most 2Dε, or sum the actual two lists of concrete one-challenge advantages. This is privacy for the specified message-only view, not security for adaptive additional openings.

The finite new hypothesis is a QPT observer of a single classical 512-bit word, either the specified block at an independent uniform 256-bit key or independent uniform 512 bits. The fixed challenger flips its own bit and checks the guess. There are no oracle queries to the challenge construction, nor a SAT statement, a public ideal cipher, or programmable randomness. The observer can implement the concrete public function coherently on its own. Its evaluation and the simulator's honest generation cost time. A reduction needs at most all 33,787 other generator evaluations, plus generation of seeds, row writes, static opening delivery and running the observer. A numerical ε must hold at that larger budget. For a target bit gap 2^(-s), the simple bound requires ε≤2^(-s)/(2D) when D>0. RFC 8439 specifies the function and test vectors; it supplies no adequate concrete post-quantum strength certificate. A new registry review would be necessary.

Preserving public testers changes the experiment. Use counter zero for incidence halves (at T use its first bit for the message), counter one with the same key and nonce for a separate full 512-bit checker at every vertex. Publish each checker. The required challenge now contains BOTH blocks under one key, versus two independent uniform words; individual one-block pseudorandomness does not justify their joint distribution. Switch every dead vertex including T. Ideal checker inversion probability at a fixed dead address is at most 2^256/2^512 by image counting, even accounting for every candidate. Across addresses sum the bounds and the corresponding hybrid costs. Placing the terminal message on a raw seed bit in this tester variant would require additional leakage security; the revised scheme deliberately obtains it from the zero-counter block. It takes 2·33789 blocks and 12972033+512·33789 issued router bits, plus the authorized source opening fields. Counter one changes one known initial/feedforward bit, retaining the block schedule.

A conservative full checker ledger uses 67,578 calls, 30,272,001 router bits and 3,256,704 static supplier bits. Emit the counter-one checker as soon as its key is sampled, then rewind the same 256 key bits and run the ordinary counter-zero block. At T retain its raw key for constructing incoming rows, compute both blocks and save its zero-block message bit in a reserved cell. The counter-one block changes only a known initial word and its feedforward summand. With the physical routines below, Enc takes at most 2,265,773,616+33,789·(51,380+512)+2·51,380+8,192=4,019,263,356 ticks. The last terms overpay for copying and restoring T. To preserve all local tester functionality a proposed-key test can locate its addressed checker and compare the full recomputed block. A decoder checking every key on its path has at most 2N+3 such keys, including its three sources and T. Take L=67,057,504 for its full framed input traversal. Per check allow 2L for finding the checker and returning to the saved row position, plus 51,380+16,384 ticks for the block and local transfers. Give it the extra counter-zero terminal block and 2·512·33,789 ticks for the longer basic scan. Together with 65,536 setup this yields at most 1,134,618,468,312 ticks. In the literal fixed-triple specialization each saved return address is part of the paid instruction sequence, and a mismatched checker can halt immediately. Using the same six-tape state envelopes described below gives 79,255,709,907,645,631,010,975,352,420 for both clocks and descriptions, below 2^97. This is an upper bound using deliberately redundant traversal. Testing selected keys does not turn a one-block assumption into a joint assumption.

### The block finite control

Four working tapes each hold four 32-bit words, with ascending bit addresses. A fifth holds rotation scratch at 12…43 and nine repeat tokens at 1…9 with blank boundaries. The key is read twice from the input. State-labelled instructions clear the guards, load all constants, nonce, counter and key, and reposition the input head. In each quarter round, one forward 32-step pass writes both an addition result with finite-state carry and the XOR with its rotation operand to scratch. Copy scratch backward into the destination with one wrap, returning relevant heads to their word starts. Rotations 16,12,8,7 all incur their actual tape movement. The double-round schedule handles columns followed by diagonals. All four heads return to zero at its end. The counter dispatch scans past already consumed zero tokens to decrement the remaining ones, or exits on the sentinel. After ten double rounds, add each original word with a new carry at each word boundary and emit 512 bits. End with every work head at its start and input advanced 256 bits.

There are 6,409 instruction positions in 508 run-length records. Only 1,488 positions consume a predecessor carry, giving 7,897 useful control encodings and one spare state. The compact list is only an authoring convenience: charge the whole registered transition table. Its five work tapes, zero oracle channels and 7,898 states have 6·7898·3^5·(4+4·5+13)=426,065,508 description bits. The declared clock is 51,380 steps. The trace consists of 780 initialization/repositioning ticks, ten 4,984-tick double rounds including their seeks, 120 token/exit ticks, and 640 feedforward/return ticks. The nine repeats cost 2r+3 at r=0,…,8 and the exit 21. Clock and description fields plus determinism are Lean-checkable; the all-keys agreement with the RFC round function follows by the described word invariant and is not a Lean functional-correctness theorem. The independent word implementation matches the transition replay on the RFC zero key, an ascending-byte key and eight seeded random keys, including the complete 64-byte zero-block test vector. [RFC 8439 §§2.3, A.1](https://www.rfc-editor.org/rfc/rfc8439#section-2.3)

A second compiled control in the same Lean definition, SharedQuarterBlock.machine, shares the identical 551-instruction quarter-round body across all eight sites. Each caller writes its three-bit return address on scratch cells 12,13,14 and enters the common routine at cell 15. The scratch word occupies 15…46 during that call. On return three bit tests in a seven-state dispatch tree recover the original continuation and restore the head to 12. Call and return add seven ticks per quarter plus one final exit tick. This gives 2,585 instruction positions, 620 carry-sensitive continuations, one spare state and 3,206 declared states. Its clock is 51,941; descLen is 168,276,528 bits on five work tapes, or 560,921,760 if adapted to six as a local subroutine. The shorter-clock version above remains a separate machine. This trade trades 561 extra ticks for 257,788,980 fewer stand-alone description bits per machine.

The first translation of the addition/XOR primitive mistakenly wrote the temporary to the rotation operand rather than scratch. We detected this by running the actual Lean transition function on the RFC vector and corrected both controls. Both final Lean transitions return exactly the RFC 512 bits after 51,380 and 51,941 steps respectively. In addition we checked every local action against its independent specification on all 3^6 head-symbol profiles and two carries: 40,824 cases for the first control and 56,862 for the shared routine. The replay reads the packed instruction runs from the submitted Lean source. With 256 independent Boolean input variables, hash-cons a symbolic XOR/majority DAG while executing the schedule; the only data-dependent control besides carry is the key-independent scratch dispatch. All 512 resulting expressions structurally equal the independent RFC word-level ripple-carry expansion (42,496 internal nodes). This is finite executable verification for all input keys under the exhibited operation semantics, not a kernel-checked Lean extensional correctness theorem.

### Complete packet and physical routing

At N=4224 there are 33,776 degree-two, 12 degree-one and a single terminal vertex, 50,672 rows and 67,564 incidence pads. Thus emission uses 33,788 blocks (1,736,027,440 block ticks before wrappers) and 12,972,033 router bits including the message. The local supplier can independently emit a fixed 257-bit field per source, namely its flag and either its 256-bit seed or zero. It reads 3N public authorization bits. With this fixed framing all source fields cost 3·4224·257 extra bits, including unopened sources; a prespecified triple alone is 768 raw opening bits exclusive of its indices.

For encryption use six work tapes. Tapes 0–4 are the same block kernel, tape 5 is a sequential packet buffer, replacing the stand-alone kernel's read-only key input. Each public index has eight 768-bit slots in order A,J,C,AL,AR,CL,CR,K; an absent boundary vertex skips its slot without generating a block. For an occupied slot sample its 256 fresh bits to tape 5, rewind, read/re-read the key by the same moves as the kernel and write feedforward results **in place** on the four row tapes. Then read them sequentially into the same slot after the original key. Reset the four row heads. One occupied slot costs 512+51,380+640 ticks; four absent slots cost at most 4·768 head moves. The unexpanded terminal key is separately sampled and kept on tape 2 once all blocks finish. The supplier emits its authorized fields during initial key sampling, retaining the current public flag as a control bit. For fixed slots these reads can coincide with writes. The body output chooses all A prefix rows upwards, A suffix rows downwards, first joins upwards, followed by C prefix, C suffix and terminal joins in the same arrangement. This only permutes the serialization of the graph; both outgoing purposes use the corresponding consistent public row order.

For each body read its incident pad fields and its destination key field (except T, held separately); sort their physical addresses and traverse the interval from the nearer extreme first. A 256-bit accumulator on tape 0 combines the fields. Initializing, updating and emitting the last XOR all take one tick per bit. Terminal rows xor the held key in parallel. Between fields move the packet head and reset both local heads in max(256,|next−position|) ticks, padding if necessary. Enumerating every address in the actual graph gives exactly 487,519,488 budgeted ticks for all body fields, before the final one-bit write. The full encryption bound is 2,265,773,616, including 1024 terminal/rewind ticks, 3N·260 mask/framing ticks and 4096 setup ticks. The local input can use encodeTuple of the mask and the one-bit message. The output is the raw packet; framing for subsequent input is charged to the decoder.

For decryption, take a framed input with the 39-bit triple and the complete local packet. Select three authorized openings by their fixed positions. Invalid or unauthorized requests can stop with zero. Retain the few active keys/pads in six 256-bit slots on work tape 5. For each required unary body, expand its parent, retain the selected half, and xor it with its addressed input row into the current key slot. At binary bodies expand both parents successively, saving one half, then xor both halves and the body. Tapes 0–4 run the same expansion with local feedforward results. A selected path has at most 2N body reads and 2N+2 expansions across both joins. All row addresses increase in the specified serialization for every compatible triple; the input head never needs a second packet scan. Holding the input head stationary during a work-tape expansion lets the decoder resume at its correct next bit. Framing each field writes true before each raw bit and false at the end. Charge at most 2(12,972,033+3N·257+39)+16 input travel and framing ticks. Add 16,384 local ticks per expansion for moving/reusing the six slots, copies and XORs, plus 65,536 setup/terminal ticks. This gives 605,128,904 total. Each local access traverses at most 1,536 cells, and at most six such transfers/seeks, six 256-bit copies, and eight 128-cell row-head resets per expansion fit the stated allowance. Only selected bits of the two four-word halves are needed.

A deliberately literal finite-control translation bounds the wrappers' **description**, including both programs. For Enc specialize the static schedule; unroll bounded loops, retaining at most two control choices per tick for carry or current opening flag. The flag is needed during random seed output only, before entering the block kernel. Its use and the actual carry need not coexist. Allow 2·EncTime+128 states. For Dec first dispatch on a fixed-width triple (fewer than 2^40 binary trie states); invalid triples halt. For each of N(N−1)^2 valid triples unroll its determined route, including the input skips, with 2·DecTime+128 states. The local slot algorithms hold arithmetic state only while the corresponding bit is processed, with no uncharged row address table. Generic control compression is possible but not assumed. At six work tapes the registered description length is 6s·3^6·(4+24+Nat.size s). For these bounds the two descriptions are 1,209,080,277,311,040 and 37,883,177,661,542,255,152,680,960 bits. Combined with both clocks this is 37,883,177,662,751,338,300,894,520, below 2^85. The companion Lean arithmetic node checks these bounds and the improved comparison and tester totals below. The outer bounds are a construction and a numeric ledger, not a Lean refinement proof of the whole transducer. They exceed a 2^32 combined diagnostic even though the two clocks alone fit. The literal outer description is dominated by the fixed triple dispatcher. The accompanying executable checks 280 compatible paths for N=2 through 6 against the actual block and recomputes the full large graph head ledger.

### Smaller decoder without a triple-indexed control table

The replay also implements a row-by-row selector requiring at most two comparisons of 13-bit indices with public constants per row. For a left range base at t, take it iff j≥t and i=t−1; for the left recurrence require j≥t and i<t−1. For a right base use j≤t and i=t+1, or i>t+1 for its recurrence. For a join at t require j=t and compare i with t to choose its side. Use k in place of i in the C phase. These rules select exactly the previous ordered path, verified exhaustively for all compatible triples at N=2…10 and at 24 deterministic sample triples for N=4224. They also follow directly by induction on the two directed ranges.

Write i,j,k once to work tape 3 at positions 154…192; the block touches only positions −1…128 on that tape. Between block calls the row heads are zero. Compare the stored 39 bits with the public constants, keeping at most three ternary less/equal/greater statuses in control, then return the head to zero. With fixed row-specific constants this takes fewer than 512 extra ticks per row and per source slot, including the selection branch. An additional 65,536 preparation ticks suffice for triple decoding and range/consistency checks. When a source field is selected, copy its 256 bits to the dedicated slot after checking its authorization flag. An invalid triple or missing required opening can return zero. Data-dependent carries during block execution never need coexist with the comparison statuses.

For a literal six-tape control description, specialize one routine per serialized row/slot, reusing it for every possible triple. Per routine allow 2^20 control states: 512 comparison positions with at most 27 statuses, two expansions of at most 51,380 ticks with two control states per tick, 2·16,384 additional buffer movements (two states per tick), 514 framed input movements and constant entry/exit dispatch; even twice the resulting sum fits. Add one more 2^20-state allowance for setup, using the same bit-serial comparators for initial validation. The improved decoder bounds are 637,626,568 ticks and 66,422,046,720 states, giving description length 18,593,922,070,609,920. With the previous encoder the combined registered-model local cost bound is **19,803,005,251,321,144 < 2^55**. These are bounds for the specified local six-tape construction, including fixed-layout authorized source delivery. The two complete wrappers remain algorithmically described and trace-costed rather than instantiated as top-level Lean Machines. Both numerical totals are checked by the same Lean arithmetic node. Using the slower shared-quarter kernel adds 561 ticks per expansion; it does not by itself refactor the expensive unrolled outer control.

### Remaining source and WE obligations

When the entire source union has a compatible triple the released string intentionally opens the terminal. Separate initially conflicting sets can pool into a compatible triple. There is an exact obstruction on the pooled sets. If A and C are nonempty, T remains closed exactly when J is contained in the union of the singleton support elements of A and C (take no element from a side of cardinality above one). For each fixed j a valid triple exists iff both sides have some entry different from j. In particular three distinct J openings suffice to open the terminal for any nonempty A and C. We checked all 299,592 mask triples for N=1…6. If these aggregate sets are themselves computable from the statement, this local authorization predicate can be decided by scanning the sets. A general construction would need a reduction that controls the joint disclosure available from all witness choices, or a mechanism that prevents pooling across them. The static supplier models real externally authorized openings and charges the bits; it does not build the policy for all witnesses of a NAND statement. The degree-one opened signed label in [PR 168](https://github.com/MachinaIO/SigabaPark/pull/168) reveals the common source root from its public affine wrapper, making all labels derived publicly from that root available. Wrapping independently generated router keys under such recoverable native keys does not implement static selective delivery. Independent role keys with genuine context-bound issuance avoid that particular identity, but the issuance and its reduction must be supplied. For a polynomial explicit context list, independent packets isolate contexts at a factor equal to the list size; this does not implement the exponentially many witness evaluations of general WE. All-circuit integration, complete security, numerical quantum assumption strength and full registered cost remain open.
