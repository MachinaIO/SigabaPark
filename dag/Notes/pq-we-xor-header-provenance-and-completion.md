Consider the 256-bit variant in [PR 131, final section](https://github.com/MachinaIO/SigabaPark/pull/131). With independent uniform K,L, the public header is h=K XOR L. The canonical source Q_K contains K as a literal. On a satisfying assignment x it returns K XOR y, and otherwise returns zero. Encryption packages h and a locked program comparing the output with L and carrying a one-bit payload. A satisfying witness holder supplies y=h. The registered primitive uses 128 inputs and 4096 NAND gates. This task investigates the additional strict aggregate budget below 2^32.

### Which hybrid the actual compiler needs

A common random translation (K,L) to (K XOR d,L XOR d) preserves h and the constraint K XOR L=h exactly. Conditional on h this traverses the same affine set of 2^256 pairs. The desired independent-header law conditional on h uses all 2^512 pairs. The total variation distance between these two *latent* pair laws is 1−2^-256. This calculation identifies an invariant of the proposed coupling. Whether any of it remains visible after compilation is a separate question about the compiler.

For arbitrary-depth inputs the GKW construction publishes the evaluation key, an LHE ciphertext for the circuit description and a low-depth locked decryption circuit carrying the payload. The public evaluator is supposed to evaluate the specified universal circuit on the encrypted description and pass the resulting ciphertext to the locked decryptor. The proof first simulates the locked decryptor, then erases the encrypted source by semantic security. The shallow matrix construction is a different interface. Its public encodings cover branching-program transitions and an output comparison. The final construction expands the circuit output by hashing and pseudorandom generation. The published arbitrary-depth wrapper has no check that an input of its decryptor is a faithful evaluation of that universal circuit. [Goyal, Koppula and Waters, FOCS 2017, pp. 615–617](https://ieee-focs.org/FOCS-2017-Papers/3464a612.pdf).

Here the auxiliary view for the *first* simulation includes both the encrypted source and h. Given the raw inner decryptor with the canonical hardwired key, its auxiliary encrypted source can be decrypted to the description of Q_K, and its K and h determine L. This reasoning concerns the information supplied in the theorem's entropy hypothesis. The public view contains a compiled decryptor. The paper's subsequent IND-CPA hop is only available after the first simulation has removed its dependence on the secret decryption key. Reversing the order would require generating the locked decryptor for the challenge key in the presence of the correlated header. Decision LWE alone does not provide that simulation in this argument.

A specification-level separation clarifies why a compiler-specific argument is necessary. Suppose a compute-and-compare compiler B supports simulation given auxiliary inputs when the independent t-bit lock has t−1 remaining bits of min-entropy, as in the asymptotic high-entropy setting. Fix any efficient descriptor bit g(P), chosen to be the first literal key bit for canonical Q_K. Form a compiler with the same evaluation algorithm and one ignored public bit b=L_1 XOR g(P). For the independent-lock specification the bit is uniform even conditioned on P, the payload and independent auxiliary data. Given these and b, the lock retains t−1 bits of entropy. Apply B's auxiliary-input simulator to this enlarged side information. The simulated package thus consists of B's simulation and an independent fair bit. Correctness is inherited. For the full XOR-header experiment this bit instead agrees with the corresponding header position with probability one; under independent header replacement the agreement probability is one half. Both claims hold on false statements. Thus even ordinary uniform-lock security and correctness together do not imply the full-header switch for arbitrary implementations. This example distinguishes abstract compiler specifications. It makes no claim that GKW's published encodings contain the extra bit, and it does not enter a WE construction.

### A provenance repair and its limit

A concrete alternative receiver binds the encrypted source c_src, evaluation key and public statement to the inner circuit. Its input specifies x,y, a claimed source NAND trace, an evaluated ciphertext c and a Boolean-wire transcript of the deterministic public evaluation of U_(x,y) on c_src. It rechecks the fixed source/parameter binding, every input and local transition of the evaluation transcript, its final ciphertext c and a satisfying original NAND trace. A topological induction through a Boolean implementation of the evaluator proves that agreement of these checks forces c to be the prescribed evaluated ciphertext. For public-coin evaluation fix its coins by the construction or specify and validate an allowed tape with a suitable correctness guarantee. Invalid transcripts return a failure-tagged word, valid transcripts a success-tagged decrypted string. The comparison target is (success,L). This also handles L=0. Serializers, lengths and the original forward-reference convention must be included.

This deterministic certificate supplies an evaluation-origin invariant without a succinct-proof assumption. In particular, on a false statement no transcript satisfies all checks. A verifier running outside an independently reachable bare decryption component does not enforce its checks on that component. They have to be inside the locked predicate. The raw *checked* predicate still holds the LHE secret key, and h and the encrypted source are still present in its conditioning data. Changing the return value on invalid transcripts does not increase the min-entropy of L given those bytes. Proving the full switch now needs either a concrete simulation of this checked predicate under the correlated auxiliary view, or an input representation in which the raw predicate and its auxiliary fields jointly leave L hidden on false statements. Equality of its Boolean behavior on false statements supplies neither reduction. This analysis does not establish such a reduction or a quantum security theorem.

In a straightforward implementation with G Boolean gates in the fixed evaluator computation, the added transcript contains one claimed output bit per gate. A decoder generating all G bits on work tape takes at least G writes, before comparison, traversal, parsing or cryptography. The original NAND trace needs 4096 gate bits in this layout. These are local decoder data, and add no external ciphertext bits when the decoder generates them. If the new public compiled package has length z' after the fixed 256-bit header, the predecessor's schedule still requires 4z' + E_extra + D_extra ≤ 3,748,295,401 under the same machine reservations. Keys, source ciphertext, and the enlarged inner compilation must all be included in z'. Binding data twice in the compiler may increase it further. There is no certified strict-clock instantiation.

### A repair that actually restores conditional entropy

Omit s specified positions of h, where 0≤s≤256, and fix their locations publicly. The retained header is the projection of K XOR L. Given the canonical source, payload, retained header and independent compiler coins, L is exactly uniform on 2^s completions. The same conclusion holds for the inner decryptor conditioned on the independent key material and encrypted source: its raw key recovers K and supplies no information on the missing positions of L. These statements refer to the conditioning data before publishing the locked obfuscation. They also hold on the false instances.

Wichs and Zirdelis consider distributional simulation conditional on the source and auxiliary data, discuss the multibit payload, and give an asymptotic sufficient (pseudo-)entropy condition. This is an actual change to the hypothesis of a candidate instantiation. It does not give concrete 128-bit security at a chosen value of s or quantum security. [Wichs and Zirdelis, FOCS 2017, pp. 600–601, 604–606, Definition 2 and Theorem 1](https://ieee-focs.org/FOCS-2017-Papers/3464a600.pdf).

For a satisfying witness x, the decoder can enumerate the missing positions of y, call the locked program on (x,y) and return the first non-rejection payload. In an ideal exact comparison exactly one completion works. Implementing it would require a global correctness bound across all such evaluations. The public header uses 256−s bits, saving s output bits and at most 4s steps in the three serial phases of the predecessor's layout when z is unchanged.

There is a sharp count for this specific decoder interface, allowing adaptive classical completion tests at the same satisfying witness. Condition on all coins independent of the uniform missing completion and payload. Record the set of completions queried on the all-rejects path, of cardinality at most q. For any missing completion outside this set the path, hence the final guess, is independent of the payload. Write good_b for the completions on which b is returned when b is the actual payload. The intersection of the two success sets lies in the query set. Their union has size at most 2^s, so their cardinalities sum to at most 2^s+q. Averaging over coins preserves this inequality. The bound is attained by q distinct trials and a fixed guess on failure for q≤2^s. The DAG theorem completion_count proves the finite-set inequality from its miss-path hypothesis. This interface explicitly excludes access to secret-dependent compiler bytes beyond their ideal equality response.

Per-message error at most 2^-128 implies (2^127−1)·2^s ≤ 2^127 q by averaging both payloads. If q itself is below 2^32, then s≤31 by completion_budget. Reserving even one machine step per test is generous. A 128-bit residual lock would already require more tests than the entire machine budget. Small s also makes the secret guessable with probability 2^-s from the raw source and retained header. This shows exactly which tradeoff the prefix truncation and enumeration repair achieves. A more promising next target is a witness-assisted recovery procedure that obtains the missing lock bits in one coherent evaluation and still yields conditional pseudo-entropy on false statements. Such a procedure needs its own explicit algorithms and a reduction. Neither certificate checking nor header truncation supplies it here.


### A public satisfying-instance check for any claimed entropy theorem

The entitlement to a common obfuscation simulator must distinguish the two kinds of instances if it is to justify full WE for correctly decrypting schemes. On the registered true fixture falseThenTrue, fix its public all-zero satisfying assignment. Suppose both payloads have correctness error at most e. The observer running honest decryption on that assignment returns one with probabilities p0≤e and p1≥1−e. Applied to a common simulator with the identical public header marginal, its acceptance probability is a single number p. Thus the larger of the two real/simulation gaps is at least 1/2−e, regardless of whether the decoder inspects compiled bytes. The theorem yes_fixture_simulator_floor proves this real inequality. Crucially, the ciphertext comparison here is on a public YES fixture. WE only requires hiding on NO instances.

In the projected-header variant the same s-bit entropy calculation holds on this YES fixture even given its fixed public witness. Therefore an instantiation claiming *concrete*, sufficiently small simulation error on every distribution solely on the strength of that s-bit calculation, at the cost of honest decryption plus fixed framing, is inconsistent with correctness. An asymptotic entropy theorem with unspecified concrete losses does not assert such an instantiation. A new witness-assisted design should show precisely why its intended adequate entropy or computational unpredictability guarantee holds for the raw predicate and all auxiliary data on NO instances, while leaving efficient lock recovery for the public YES fixture possible. Giving the actual reduction the full raw pad on both sides, or fixing the same residual entropy on both sides and claiming a tight universally applicable simulator, fails this check.
