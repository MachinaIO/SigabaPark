### One encrypted table per chunk and one key

The fixed instance has 128 witness bits and 4096 NAND gates. Split the witness into k positive widths b_i summing to 128, with n_i=2^b_i possible values in slot i. Enc operates the entire private MIFE setup. Publish each slot's n_i encryptions in canonical public order with independently sampled encryption coins. Generate one private function key for the same-shaped circuit g_beta(v)=beta AND phi(concat v), using the original evaluator and encoding conventions. Include the key in the ciphertext. Dec selects one entry per chunk using its witness and invokes deterministic MIFE decryption. The message bit is a private circuit constant. Compared with a separate encrypted payload at a singleton coordinate, this puts the payload in the key and saves one input coordinate. Only public labels are encrypted. Their ciphertexts still authenticate the inputs to the private function key.

The left/right game asks for equal plaintexts in every slot and the single differing function pair (g_0,g_1). The entire query list is fixed before setup for each statement. Every Cartesian tuple of queried plaintexts produces equal outputs exactly when the statement has no witness. This is Definition A.2 admissibility. The lemma full_table_admissibility proves this equivalence under a surjective tuple-to-witness map. Here cutting a witness at the chosen boundaries is an explicit right inverse to concatenation. Unqueried or cross-run key combinations are outside a single ciphertext, and the security experiment still permits arbitrary processing of the whole public package. A simulator that only answers along a chosen witness path would be insufficient. Correctness on each fixed satisfying witness is the ordinary per-tuple correctness requirement; keys and all other entries are generated honestly. A quantitative instantiation must bound this error by 2^-128. The registered notion does not demand one simultaneous correctness event across every witness.

For each fixed false statement, let the WE observer guess the private MIFE challenge bit from precisely that package, including the framing supplied in the WE game. This gives the same ordinary distinguishing gap, equal to twice the absolute MIFE guessing bias under a fair challenge bit. No hybrid over 2^128 witness tuples belongs in this wrapper. Function privacy is essential: merely encrypting the public labels under message-private FE would allow the functional key itself to reveal beta. [Brakerski, Komargodski and Segev (BKS), ePrint 2015/158, §§2.2–2.3 and Appendix A.1, Definitions A.1–A.4](https://eprint.iacr.org/2015/158.pdf).

### What the selective compiler emits

Use Theorem 3.1 for two inputs and Theorem A.5 for higher arity. The fixed encryption lists allow the selective-message compiler. The construction's Figure 5 key issuer returns a key under a fresh child master key. The Figure 6 aggregator returns child ciphertexts using pseudorandom coins. At arity r, a first-coordinate entry consists of one base ciphertext under the outer key and one (r−1)-input aggregator key under the inner key. Each later entry descends into precisely one coordinate of the inner scheme. A selective r-input key is itself one base functional key. In these instructions base means the chosen private single-input FE implementation after any required security transformations. This uses the typed setup, algorithms and Theorem A.5 statement from Appendix A.2; some overview sentences refer instead to a fully secure child.

Induction gives these counts, with no simultaneous evaluation of Cartesian tuples.

* Public base ciphertexts E = sum_i n_i. Public base functional keys K = 1 + sum_(i<k) n_i. The final coordinate has no aggregator key. Setup for one arity-r master key calls r base setups, and each first-coordinate encryption at arity r>1 samples an additional child master of arity r−1. Thus direct honest base setups total k + sum_(i<k)(k−i)n_i, outside the algorithms subsequently evaluated under FE.
* One selected tuple invokes D_1=1, D_r=2D_(r−1)+1 base decryption calls. The two children respectively compute fresh ciphertexts and the final result; the extra call derives a key. The formal lemma literal_dec_calls yields D_k=2^k−1. These calls can have very different costs and output sizes.
* The bounded number of keys under the single outer master is one. In the real inner setup, there are n_1 aggregator keys at the next level, then n_2 at the next and so forth. At base setup level i>1 this gives n_(i−1) keys and n_i ciphertexts under the corresponding base master. The paper separately requires query capacities for the ephemeral child masters in the proof. For two inputs §3, pp. 14–15, explicitly requires capacity for both coordinate counts at the starred master and for the functional key queries. Single-key security globally cannot justify all these inner uses. Section 2.2 distinguishes bounded LWE-based and small-depth-PRG-based schemes from the one-way-function case with a single key and message query.
* For a literal repair using a separate one-key FE instance per known key request, each of the n_i ciphertexts at setup level i>1 has n_(i−1) copies. Even before other objects this writes at least n_1 + sum_(i>1)n_(i−1)n_i bits if each copy is nonempty. With eight equal 16-bit chunks a single adjacent product is 2^32. This bound concerns explicit replication only. It does not apply to all bounded FE. If the one-key base also supports only one ciphertext, it further requires independent instances or a separate multi-message construction. A bounded many-key FE must be priced at its actual capacities.

Let O=E+K. In a literal layout of nonempty objects using at least B bits each and a literal recursive evaluator using D steps exclusive of nested calls per base call, a necessary budget test is B O + D(2^k−1) < 2^32. Encoder output writes and decoder steps are distinct contributions. Add actual header/framing bits, table scans on the sequential machine, generation of keys and ciphertexts, the statically sized nested circuits, sorting/dispatch if used, and both machine descriptions for an upper bound. The sound tighter expression uses the sum of the individual object bit lengths and a separate clock for each selected call.

For fixed k, put y_i=b_i+1 at nonterminal slots and y_k=b_k. Then O=1+sum_i 2^y_i and sum y_i=127+k. Transferring one unit from a width at least two larger to a smaller width reduces the power sum whenever the resulting widths are allowed. At k=13 the adjusted widths can be ten 11s and three 10s, giving O=23,553 and D_k=8,191. At k=14 use one 11 and thirteen 10s, giving O=15,361 and D_k=16,383. Either arrangement reaches 31,744 combined sites. The theorem literal_site_floor proves this is a global lower bound over every k and width allocation, using supporting lines for powers of two at 10 and 13. It is a sharp *unit-count* optimum. If each emitted object and each base decryption costs at least the same 135,301 units in its respective resource, direct implementations exceed the cap. The gate numbers alone establish no such common lower price.

### Removing a public coordinate and the security price

One can replace a whole prefix of a public witness with functional keys. For a prefix of total width B, generate a key under the same suffix MIFE master for each of its 2^B values a, for the function g_(a,beta)(v)=beta AND phi(a||v). Emit only the suffix ciphertext tables and these indexed keys. For *each* query pair of such functions the entire suffix Cartesian product passes the left/right test on a false statement. Honest decryption uses the key indexed by the actual prefix. This requires bounded function privacy for 2^B key queries. It is a distinct multi-key specialization, while the construction above issues one outer key.

Peeling just slot 1 of a k≥2 construction saves n_1+1 base public objects in total and changes the recursive decryption count to 2^(k−1)−1. The new key count is n_1 + sum_(2≤i<k)n_i and ciphertext count is sum_(i≥2)n_i. The top key load rises from one to n_1, and issuing those keys costs real work and bits. At k=8 with 16-bit slots the counts become 458,752 ciphertexts, 458,752 keys and 127 base calls. Removing more prefix slots instead multiplies their outer key count. This gives an algorithmic tradeoff in a specified security game and is independent of the size of an implementation of single-input full FE.

### Reduction loss, assumptions and remaining checks

At a selective step of arity r≥2, BKS Appendix A.2, proof of Theorem A.5, equalizes the counts to a bound T. It uses two initial and two final transitions and seven transitions per first-coordinate row, for 7T+4 comparisons. This is a proof count and is distinct from D_r and O. In the construction the first-row index j runs over the n_1 ciphertexts; using T=max of the per-slot and key query bounds is conservative and avoids assuming a sharper asymmetric theorem. Duplicating already-admissible queries if equalization is needed preserves admissibility. An implementation does not publish dummy rows for this proof convention.

For clarity about a source-level typing issue, Claims A.6 and A.16 use the child scheme, A.7 and A.15 the outer base scheme, and A.8–A.14 handle a single j. The input and output wrap/unwrap transitions A.8/A.14 are child calls, A.9/A.13 outer base calls, and A.10/A.12 PRF calls. A.11 changes the contents and functional key of the starred master; the displayed bound says single-input FE although the starred master in Figure 5/6 has arity r−1 and supplies coordinate-specific encryptions and a key for C_f. For r>2 a quantitative implementation must give the *child* challenge there and prove the conditioning/admissibility and query bounds for that reduction. The child's messages commit to the prefix row and leave the remaining slots variable. Their plaintext outputs under the restricted functions coincide by the same full Cartesian validity test. This establishes that semantic requirement. Following the printed single-input symbol for this hop at every r would undercount the recursive loss.

The typed comparison tree has 3T+2 child terms, 2T+2 base FE terms and 2T PRF terms per rank. For a uniform per-rank capacity T its leaf count obeys H_1=1, H_r=(3T+2)H_(r−1)+4T+2. This is the stated hybrid schedule with the typed child at A.11, before the underlying single-input FE or PRF is reduced to any lattice challenge. In particular for k=8,T=65536, log2 H_8 is about 124.32. No honest algorithm materializes H_8 ciphertexts. Wrapper costs can still be large because hybrid reductions generate whole ciphertext lists and keys, including the hardwired values in inactive branches.

One conservative normalization directly handles BKS's fair-bit guessing experiment. If each individual transition is bounded by the corresponding ordinary distinguishing gap plus separately accounted bad events, bound the ordinary output gap by twice the sum of the hybrid terms. With a common bottom comparison bound delta, zero bad-event terms and the same query cap T at all levels, this gives delta_WE ≤ W_k delta, with W_1=1 and W_r=2((3T+2)W_(r−1)+4T+2). Tighter normalizations are possible after specifying every wrapper. For k=8,T=65536, log2 W_8 is about 131.32. If bottom gaps actually satisfy delta^2 ≤ rho·cost(A)/2^P for an observer of cost at least one, the conservative sufficient strength is P≥128+ceil(2 log2 W_k)+ceil(log2 rho). The k=8 example already calls for at least 391 bits when rho=1. This is a sufficient strength under the stated loss accounting, not a measured attack threshold. Finite randomness errors, including tag collisions if a hop treats independently sampled tags as distinct, and losses from FE security transformations must be added with their own coefficients. For N uniform independent lambda-bit tags in one collision-sensitive scope the birthday union bound is N(N−1)/2^(lambda+1); one must count the actual scopes before assigning parameters. The paper gives asymptotic negligible errors and supplies no 391-bit registry certificate. Increasing a base security parameter changes real key lengths, circuits, sampler precision and clocks. Repeating encryption does not by itself amplify computational hiding or prove the required squared-gain inequality.

This construction uses a fixed k and the finite bounded-query specialization of the private compiler. A succinct growing-arity private MIFE for arbitrary functions would violate the project's exclusion of primitives known to imply iO: for an n-wire Boolean input publish encryptions of both bits at each wire and a key for either of two equal padded circuits. The same Cartesian argument is then exactly the security argument for obfuscating equal circuits. BKS §1.2 records this equivalence for polynomially many inputs. Here dividing a growing input among a fixed number of tables can require exponential issuance. Fixed-arity bounded FE is a construction route to be reduced to admitted assumptions; assuming unrestricted succinct private MIFE as a new hardness premise would change the problem. [BKS, §§1.2–1.3, 2.2, 3 and Appendix A.2](https://eprint.iacr.org/2015/158.pdf).

The single-input results cited by BKS do not complete the post-quantum claim. The LWE-based route cites GKP+ for bounded keys, requires message and function privacy for nested key-issuing circuits, and must cover the actual table and reduction query bounds. GKP+ succinctness allows depth dependence; it does not fix the lengths of these concrete objects. A quantum-safe reduction for a quantum observer receiving classical ciphertexts, concrete admitted assumption parameters, finite errors, and measured or proved canonical machine clocks and description sizes remain open. The existing k-split notes identify a different multi-input ABE requirement. Here the private functional key itself carries the bit and its full function-privacy game is the essential resource. [Goldwasser et al., STOC 2013](https://people.csail.mit.edu/nickolai/papers/goldwasser-sfe.pdf).
