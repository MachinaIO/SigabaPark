The published general-circuit compiler for the 256-bit XOR header needs **more than 2^120 raw bits in its array of starting matrices**. The registered cap is 2^100 for both machine clocks and descriptions combined. With GKW's displayed affine hash family, one starting matrix already exceeds 2^100 on a supported choice of coins. These bounds use the parameter regime and the finite sampler properties in GKW. They apply before pricing encryption of the circuit, transition matrices or tape travel. They do not give a lower bound on witness encryption from LWE.

### Which program gets compiled

Use independent uniform 256-bit strings K and α, an external header h = K XOR α, and one payload bit. The program P on (x,y) outputs K XOR y on acceptance of the registered NAND circuit and zero otherwise. The compiler budget in question is for Z = Obf(P,α,msg). The predecessor's strict schedule allows 4z + E_extra + D_extra ≤ 3,748,295,401 for z = |Z|, hence at most 937,073,850 bits even with both extra clocks zero. The registered cap is a separate, larger target. [PR 131, final subsection at the specified commit](https://github.com/MachinaIO/SigabaPark/blob/3c23950ff7c638f49022087d73210ffbdeb475cd/dag/Notes/pq-we-streamed-clock-and-guard.md)

Goyal, Koppula and Waters (GKW) use two circuit evaluations. The outer evaluator homomorphically evaluates a universal circuit with (x,y) fixed on a bitwise LHE encryption of the description of P. It obtains 256 evaluated bit ciphertexts. The inner program decrypts those 256 ciphertexts with the hardwired LHE secret key, hashes the result with a hardwired pairwise independent hash, and applies a low-depth PRG. Its r output bits are compared to PRG(hash(α)) inside the matrix construction. Write c for the evaluated LHE ciphertext width, D for the sum of the decryption, hash and PRG depths, and L for the length of each component program. Theorem 2.2 gives width five and length 4^D for a fan-in-two circuit. Corollary 2.2 pads the selector to a public cycle, yielding **L = 256 c 4^D** for the literal Section 4 compiler. The registered statement can have sequential depth 4096. Its gate count gives no depth-12 guarantee. Its depth enters the outer LHE evaluation and key choice. The branching program in Section 4 processes the inner program. Section 1's direct branching-program explanation omits the general-circuit LHE wrapper and parts of the expanded lock. [GKW, ePrint 2017/274, revision of July 16, 2017, §§2.2, 2.4, 2.6 and 4, pp. 12–18](https://eprint.iacr.org/2017/274.pdf)

### Actual fields, coins and evaluation

Let n be the component LWE dimension, m the column count of the stacked trapdoor matrix, w = ceil(log2 q), p the program description length, f the padded width of a fresh LHE bit ciphertext, and e the evaluation-key size. The paper specifies algorithms and dimensions, leaving the bit encoding and the LHE instantiation to the implementation. The following is an exact raw payload count for public fixed widths, row-major arrays, and no redundant indices.

| Public field | Multiplicity | Bits |
|---|---:|---:|
| External h | 1 | 256, outside z |
| LHE evaluation key | 1 | e |
| Fresh LHE encryption of P | p bit ciphertexts | pf |
| Starting block B(i,0,1) | r | rn m w |
| Transition C(i,j,b) | 2rL | 2rL m²w |
| Total compiled z | | e + pf + rnmw + 2rLm²w |

The other four start states per track, intermediate B blocks, trapdoors, S and E, constrained top blocks, plaintext K, lock α, hash description and compressed lock are internal. The 256 evaluated LHE ciphertexts arise at Dec. Their bits select which of two transitions to use at each level. Public dimensions and the paper's cyclic selector can be fixed in the machine. A variable layout would have to pay for its description. [GKW, §4, Obf steps 1–6 and Figures 1–2, pp. 17–20](https://eprint.iacr.org/2017/274.pdf)

A literal sampler consumes 512 fair bits for K and α and, for GKW's affine hash with s output bits, 257s fair bits. It needs one LHE setup, p independent bit encryptions, rL independent TrapGen calls on 5n by m matrices, and 2rLm calls to the vector SamplePre routine (m columns of each of 2rL matrices). It draws 2L n² small entries for S and 10rLnm for E. Figure 1 replaces a singular S by the identity. Conditional on the compressed lock and message, all but one of the 5r top blocks are independent uniform n by m mod-q matrices. Solving for the remaining block realizes their exact joint law. These private top choices **alone** need at least (5r−1)nm log2 q random bits in the worst case by support counting. A bounded tape with R fair coins reaches at most 2^R outcomes. For a non-dyadic modulus exact uniform draws may have no fixed fair-coin clock. Approximating the joint uniform law within δ requires 2^R ≥ (1−δ)q^((5r−1)nm). Sampler-call counts do not equate a Gaussian draw to one fair coin. Coins and output can overlap in time.

After one LHE evaluation, Figure 2 performs rL products of an n by m accumulator and an m by m selected transition, (r−1)nm modular additions to sum the results, and the norm tests on the sum and its last m−n columns. Dense schoolbook products take exactly rLnm² scalar residue multiplications and rLnm(m−1) additions, before the final sum. Faster multiplication or a streaming implementation changes this arithmetic count. These operations are not one-step bit-tape instructions. Honest matching inputs in the ideal algorithms are covered by Claim 4.2. An implementation must include total sampler, representation and LHE correctness error in the registered 2^-128 allowance. [GKW, Defs. 2.1 and 2.5, Figures 1–2 and Claim 4.2, pp. 11, 13 and 19–23](https://eprint.iacr.org/2017/274.pdf)

### A lower bound using the published parameter requirements

Write u = log2 q. GKW require q ≤ 2^(n^ε) with ε < 1/2, sufficient width and smoothing for the 5n-row trapdoor sampler, PRG expansion r exceeding nmu for the top-matrix extraction step, and the displayed correctness inequality

    r L (m² σ)^L < q^(1/4).

We use the displayed parameter bullet and the error recurrence of Claim 4.1. They agree on m²σ. One subsequent prose sentence has mσ. The Section 4 example is an asymptotic family with n = λ^(4c₀/ε) for a compiler-dependent exponent c₀. It does not give concrete registry strengths at λ = 128. [GKW, Def. 2.1, §4 parameter list, Claims 4.1 and 4.6, pp. 11, 17, 20–21 and 28](https://eprint.iacr.org/2017/274.pdf)

1. Def. 2.1 demands a preimage for every target. Counting images of a map from m residues to 5n residues gives m ≥ 5n. The promised coordinate bound B = √m σ must satisfy B ≥ 1 for a nonzero syndrome. Thus m²σ ≥ m^(3/2) ≥ 5^(3/2) > 8. This uses no hidden constant from an asymptotic smoothing bound.
2. Since r,L ≥ 1, correctness gives u > 12L. The modulus ceiling gives n ≥ u². Set t = 12L. Then n ≥ t², m ≥ 5t², w ≥ t and r ≥ nmt. A single base block costs at least 5t^5 bits and the number of such blocks is at least 5t^5.
3. Consequently **z_base ≥ 25(12L)^10**. The integer theorem `base_field_floor` proves the bound and the strict comparisons at L = 1, 62 and 256 from those four weakened finite inequalities. The real-arithmetic theorem `component_parameters` derives the modulus and dimension floors from the relaxed fourth-power correctness inequality, q ≤ 2^√n, m ≥ 5n and B ≥ 1. Relating the paper’s sampler and serialized fields to these finite hypotheses is a mathematical argument; no GKW algorithm has been formalized here.

| Relaxation, for lower bounds only | L | n floor | m floor | One base block, bits | Whole base array, bits |
|---|---:|---:|---:|---:|---:|
| One level granted | 1 | 144 | 720 | 1,244,160 | 1,547,934,105,600 |
| First integer L at which this bound exceeds 2^100 | 62 | 553,536 | 2,767,680 | 1,139,815,824,261,120 | > 2^100 |
| c = 1 and D = 0 granted | 256 | 9,437,184 | 47,185,920 | 1,367,968,386,813,788,160 | > 2^120 |

Even a single level violates the strict PR 131 inequality with zero extra work. The literal compiler has at least 256 levels for every registered statement. At that floor the schoolbook multiplication count already exceeds 2^142. A machine that emits the base field needs more than 2^120 Enc clocks from one-bit writes alone. This refutes the literal layout under the registered cap independently of any Dec schedule. None of the rows simultaneously satisfy the full parameters. They deliberately round down every cost.

**One matrix on a concrete input.** Take 4095 copies of gate (4224,4224) followed by (4224,4223), with x = 0^128. The last wire is unavailable at each read of 4224 and reads true. The preceding computed wire is false, so the final gate accepts. Choose K = 0^256, α with its first bit set and the others zero, and the honest header h = α. In the displayed affine family one allowed hash has an output row of 256 ones. That parity depends on every input, so fan-in two requires hash depth at least eight on this choice. The fixed-depth Section 4 layout then has L ≥ 256·4^8 = 2^24. One starting matrix has at least 5(12·2^24)^5 > 2^140 bits. The 2^120 array exclusion above already holds regardless of the hash draw.

There is also a bound independent of the suggested modulus ceiling. Short preimages reach at most (2 floor(B)+1)^m targets. Since 2 floor(B)+1 ≤ 3B ≤ m²σ, surjectivity implies 5nu ≤ m log2(m²σ). Substituting the correctness inequality yields m > 20nL. With r ≥ nmu and u > 12L, the base-array floor is (240n²L²)^2 bits. On the same literal L ≥ 2^24 layout this exceeds 2^100 even for n = 1. This supplementary argument still uses GKW's correctness certificate and extraction length.

### Compact statement and trace representation

A fixed family can describe the statement and K by 8,192 parent addresses of 13 bits each followed by 256 bits, exactly **106,752 plaintext bits** before LHE. The registered unary input must still be read and parsed. A fixed interpreter handles addresses 0 through 4224 and maps unavailable parents to true. Its structure and the 256 output slots depend only on the public dimensions. With this explicit family interpreter, p = 106,752 in the field table. An implementation encrypting a general-purpose netlist must substitute its own serialized length.

An alternative input to the protected predicate contains (x,y,T), where Dec deterministically computes the 4096 gate values T from its original 128-bit witness using 4096 NAND operations and two indexed reads per gate. No extra witness or trace is transmitted by Enc. The program checks each T_i against the NAND of its addressed inputs from x, the earlier T entries or the default true wire. It conjoins all checks with the final trace bit and masks each K_i XOR y_i by that flag. The protected input has 4480 bits. On every fixed x there is exactly one consistent T, and its last value is the registered evaluator's output; see `trace_unique`. On an invalid trace the protected output is zero, including when α happens to be zero. This is a new protected input interface. Its honest functional equivalence and false-statement trace soundness do not transfer a theorem about the joint distribution of compiled bytes for a different interface.

For hardwired parents, use one NAND for the expected gate bit, four for XOR with the claimed bit, and an inverter to test equality. Use a balanced tree of 4096 two-NAND ANDs for the 4097 flags. Use four NANDs for each header XOR and two for each final AND. This gives exactly **34,304 NANDs, depth at most 33**, with repeated operands allowed. For the compact descriptor encrypted bitwise, the evaluator may instead hardwire its supplied (x,y,T) and interpret each encrypted address with an 8192-leaf multiplexer. At gate i the leaves are constant true for forward and padding references. Each of 8192 lookups uses 8191 three-NAND multiplexers and 13 shared selector inverters, depth at most 27. The complete fixed interpreter uses at most **201,442,816 homomorphic NAND gates at depth 60**. This explicitly prices a family-specific universal evaluation on the compact description. These are Boolean circuit counts. The output of this stage is still 256 evaluated bit ciphertexts. The Section 4 base-field bound is identical for either description. Exhaustive two-gate checks covered all 2,048 circuit, assignment and trial-trace cases with one input, including self-references, repeated operands and forward reads.

A direct low-depth route would use the trace checks in a Barrington program and would need to retain the hash and PRG expansion for GKW's top-matrix proof. For an explicit shared selector, encode T_i = NAND(a,b) by the three clauses (¬a ∨ ¬b ∨ ¬T_i), (a ∨ T_i) and (b ∨ T_i). Each output predicate is the AND of 12,288 clauses, the final trace bit, and one literal y_i or ¬y_i selected by K_i. Pad to a balanced AND tree of 16,384 children and each child to a four-leaf OR tree, using constant literals as needed. With fan-in two this gives depth 16, counting negated literals as complemented input tests. In the standard commutator construction each child program occurs twice per level, so every leaf position occurs 2^16 times in a length-4^16 width-five program. All 256 programs have the same leaf addresses except for one y literal in the tree. At each occurrence of that position, scan all 256 y bits and use the identity on the 255 inactive reads in each track. Other positions read a common address (a fixed dummy suffices for constant instructions). This gives a common public selector of length at most **4^16 + 255·2^16 = 4,311,678,976** for the 256 raw predicates, independent of K. Negation swaps or adjusts the branch permutations without changing their addresses. The schedule is a concrete representation of the Boolean checks; it omits the hash and PRG and hence cannot be substituted directly into the security proof. The inner program of the general-circuit compiler has different input and depth. Neither 4096 gate checks nor the 34,304-gate circuit count measures matrix-chain length. In particular a generic sequential state trace is not automatically a width-five permutation branching program.

### Proof-preserving compression and its limit

**Pack only short coordinates.** For each C coordinate take its canonical centered representative a, bounded by B under Def. 2.1, and emit a + floor(B) in v = ceil(log2(2 floor(B)+1)) bits whenever v < w. Otherwise retain the original residue. This costs exactly e + pf + rnmw + 2rLm² min(v,w) bits. Subtracting the offset and reducing modulo q recovers the original residue exactly. Extend encoding to a total public map by giving malformed inputs a fixed fallback. Applying this map after each real or simulated output preserves each distinguishing bound by composition with the map, charging its clock. Correctness on honest outputs is unchanged. The sampler and the base field are unchanged. Exhaustive integer round trips for bounds 1 through 64 agreed at every coordinate, including the endpoints and width transitions. Even ideal elimination of the entire transition array leaves the 2^120 obstruction.

**Can a lossless code also shorten the bases?** Def. 2.1 gives a start block within the TrapGen statistical error δ of uniform by projection. If δ ≤ 1/2, its support contains at least q^(nm)/2 blocks. The r independent level-zero trapdoors give at least (q^(nm)/2)^r possible public base arrays; generating later fields does not remove an earlier outcome. A code that recovers each entire honest array must therefore use at least r(nmu−1) bits in the worst case with fixed padding (within one bit for arbitrary variable-length strings). This also exceeds 2^100 at L ≥ 256. Publishing a short seed for correlated bases and corresponding conditional preimages would change the distribution and require a reduction covering the trapdoor simulation. Encoding the literals losslessly cannot implement that change.

**Can one shorten the selector?** GKW explicitly allow a fixed public selector shared by all tracks. One may delete globally idle padding columns from a public Barrington schedule *before* Comp-Gen when both permutations are identities on every track for all constants of the fixed shape. The shortened permutation products agree on every input. Fresh Comp-Gen at the new length retains both branches at every retained level and the same top constraint. Figures 1–2 and the level hybrids use common selectors and permutations. A schedule depending on a private key or hash would also have to be simulated. Simply deleting already sampled C matrices would break the level equations.

Even a customized selector for the inner program can need all 256 ciphertext blocks. A nonconstant PRG differs on two neighboring seeds b and b XOR e_j (follow a cube path). Take the supported affine hash with offset b and every column e_j. Decoding an all-zero plaintext tuple and changing any one block to a valid ciphertext decrypting to one changes the same output bit of PRG(hash(·)). Different blocks can be varied independently in the domain of the inner program. The theorem `essential_blocks` proves that any fixed trace computing a function with this dependence has at least as many reads as essential blocks, even if a read supplies a whole block. A fixed schedule valid for all allowed choices of hash therefore still needs L ≥ 256. This particular argument concerns worst-case fixed schedules, independently of how often the displayed hash occurs.

The composed advantage must obey 2^128 Adv² ≤ observer cost in the registered classical model. A size decrease alone supplies none of those facts. The separate correlated-header proof obligation is unaffected. No registry premise or security target has been added.
