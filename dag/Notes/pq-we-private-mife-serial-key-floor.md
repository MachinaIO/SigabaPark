### Which implementation is covered

The arity-r key in BKS encrypts a circuit D_f whose output is a fresh serialized arity-(r−1) function key. This happens even when the ultimate user asks for one output bit. Consider the conventional string-output lift that issues a separate elementary one-bit FE key for every bit of D_f's output. Suppose each component consumes at least B bits of actual output, even if the selected circuit is constant. Use fixed-width or padded output wires for all possible child keys, fresh explicit serialized components per wire and per published function key, and no deduplication, interning or algorithmic key compression. If K_r is the minimum bit width of such a rank-r key for one final output bit, K_1 ≥ B and K_r ≥ B K_(r−1), hence K_r ≥ B^r. Any additional function-hiding wrapper must retain these fields for this lower bound to apply. This counts bits emitted on the tape. It is independent of how many hybrids a reduction uses. [BKS, Appendix A.2, Figure 5 and key-generation algorithm](https://eprint.iacr.org/2015/158.pdf).

For the explicit bit-output succinct FE of Goldwasser, Kalai, Popa, Vaikuntanathan, and Zeldovich, Section 3 forms the base function key using a tuple of one ABE key for each of the λ bits in a compact FHE ciphertext. With nonempty individually encoded fields this gives B ≥ λ even using the weakest possible field bound of one bit. Any concrete parameter choice with λ ≥ 128 therefore satisfies the hypothesis B ≥ 128. The asymptotic theorem does not give a finite registry realization or a universal 128-bit minimum for every admissible FE. The FE input ciphertext includes λ ABE ciphertexts and a garbled FHE decryption circuit; the ABE attributes include the public FHE key and an FHE ciphertext for each input bit. This shorter lower bound requires none of those extra costs. [Goldwasser et al., STOC 2013, Section 3, FE.KeyGen and FE.Enc](https://people.csail.mit.edu/nickolai/papers/goldwasser-sfe.pdf).

### Prefix specialization still exceeds the write cap

Let p prefix bits be dispatched by publishing one functional key for each of the 2^p fixed prefixes, and let r remaining slots have widths b_i with p + sum b_i = 128. If any one table has at least 2^32 entries, emitting even one bit per entry exhausts the cap. Otherwise each b_i ≤ 31. The keys alone take at least 2^p B^r bits under the layout above. If B ≥ 128 and those keys fit strictly below 2^32 bits, then p+7r ≤ 31, and hence r ≤ 4. Coverage would force 128 ≤ p+31r ≤ 31+24r ≤ 127. The Lean theorem serial_key_floor proves the equivalent inequality 2^32 ≤ 2^p 128^r under the table bounds. This includes unequal partitions and p=0. Holding only a seed or one copy of a repeated subkey changes the representation, distribution and decryption algorithm and requires its own security and cost proof.

There is a sharper threshold for the elementary lower estimate L = 2^p B^r + sum_i 2^b_i, charging one bit per nonempty row in addition to the serialized keys. For positive integer B the exact universal rejection threshold for this estimate is 84 bits. To see sufficiency suppose the estimate could be less than 2^32 with B=84. Every width is at most 31. If r≤3, coverage forces p≥35. If r≥6, then 84^6 alone is enough. When r=4 and p≥9 the keys suffice. For r=4 and p≤8 the four widths sum to at least 120, giving at least 4·2^30 row bits. For r=5, p≥1 gives at least 2·84^5 key bits. At r=5, p=0 balancing widths gives two 25s and three 26s, so L ≥ 84^5 + 2^28 = 4,450,554,880. The balancing bound follows by moving one unit from the larger of two widths differing by at least two to the smaller. For necessity at B=83, the very same five widths yield L = 83^5 + 2^28 = 4,207,476,099, strictly below the cap. This only shows the coarseness of the lower estimate at B=83. The remaining 87,491,197 units need to cover all actual row bits beyond the first, key-generation work, decryption and descriptions. The case argument for 84 is informal; the separate key-or-single-table theorem for 128 is machine-checked.

A native string-output FE may amortize the child key over output wires. Agrawal, Maitra, Vempati and Yamada, Section 4, specify LWE-based KPFE with a bounded-depth circuit returning a fixed-length string and a dynamic per-ciphertext collusion bound. Section 4.1 KeyGen outputs the entire underlying single-key KPFE key for C alongside a separate CPFE key. Enc produces a CPFE ciphertext for a PRF-randomized circuit that encrypts the input under a supplied underlying public key. The dynamic-bound compiler thus retains any explicit bit-parallel cost of the single-key scheme. Setting the inner string-output scheme to a parallel lift of the cited GKPVZ scheme gives the same conditional key obstruction under explicit serialization. The dynamic-bound compiler alone cannot supply an amortized encoding for an inner scheme that lacks one. The abstract states that ciphertext size grows linearly in the declared collusion bound, which also needs to be priced. A different amortized single-key string-output implementation, a costed conversion to full private function and message security for the required query counts, nested depth and width parameters, and finite quantum reduction clocks and advantages remain open. [Agrawal et al., ePrint 2021/848, Sections 4 and 4.1](https://eprint.iacr.org/2021/848.pdf).
